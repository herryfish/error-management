### 2.2 核心状态机组件

```
┌─────────────────────────────────────────────────────────────────────┐
│                    掌握状态机 (Mastery State Machine)                │
│                                                                     │
│  ┌───────────────────────────────────────────────────────────────┐  │
│  │                      状态定义                                 │  │
│  │  • PENDING: 待确认                                          │  │
│  │  • UNMASTERED: 未掌握 (待重做)                               │  │
│  │  • IN_PROGRESS: 重做中                                       │  │
│  │  • CONSOLIDATING_1: 第一次巩固 (间隔1天)                      │  │
│  │  • CONSOLIDATING_2: 第二次巩固 (间隔7天)                      │  │
│  │  • CONSOLIDATING_3: 第三次巩固 (间隔30天)                     │  │
│  │  • MASTERED: 已掌握                                          │  │
│  │  • WEAK: 薄弱 (反复错/直接看解析)                            │  │
│  │  • SIMILAR_GENERATED: 已生成相似题                            │  │
│  └───────────────────────────────────────────────────────────────┘  │
│                                                                     │
│  ┌───────────────────────────────────────────────────────────────┐  │
│  │                      状态转换规则                             │  │
│  │                                                               │  │
│  │  [录入] → PENDING → UNMASTERED → IN_PROGRESS                  │  │
│  │                                 │                             │  │
│  │              ┌──────────────────┼──────────────────┐         │  │
│  │              ↓                  ↓                  ↓         │  │
│  │         [做对]              [做错/不会]        [看解析]      │  │
│  │              ↓                  ↓                  ↓         │  │
│  │    CONSOLIDATING_1        引导模式            WEAK/重置     │  │
│  │              │                  │                             │  │
│  │        [间隔1天]           [引导后做对]                       │  │
│  │              ↓                  ↓                             │  │
│  │         [再做对]         进入巩固队列                         │  │
│  │              ↓                                               │  │
│  │    CONSOLIDATING_2                                           │  │
│  │              │                                               │  │
│  │        [间隔7天]                                             │  │
│  │              ↓                                               │  │
│  │         [再做对]                                             │  │
│  │              ↓                                               │  │
│  │    CONSOLIDATING_3                                           │  │
│  │              │                                               │  │
│  │        [间隔30天]                                            │  │
│  │              ↓                                               │  │
│  │         [再做对] → MASTERED                                  │  │
│  │                                                               │  │
│  │  连续错2次 → 触发相似题生成                                  │  │
│  │                                                               │  │
│  └───────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────┘
```

#### LLM配置系统设计

**配置方式**：
1. **环境变量**：适合简单配置和Docker部署
2. **配置文件**（JSON/YAML）：适合复杂配置和版本管理

**配置示例**（环境变量）：
```env
# 主LLM配置
LLM_PRIMARY_PROVIDER=openai
LLM_PRIMARY_MODEL=gpt-4-vision-preview
LLM_PRIMARY_API_KEY=sk-xxx
LLM_PRIMARY_API_BASE=https://api.openai.com/v1

# 降级LLM配置
LLM_FALLBACK_PROVIDER=anthropic
LLM_FALLBACK_MODEL=claude-3-opus-20240229
LLM_FALLBACK_API_KEY=sk-ant-xxx
LLM_FALLBACK_API_BASE=https://api.anthropic.com

# 降级策略
LLM_FALLBACK_ENABLED=true
LLM_FALLBACK_RETRY_COUNT=2
LLM_FALLBACK_TIMEOUT_MS=30000
```

**配置示例**（JSON配置文件）：
```json
{
  "llm": {
    "primary": {
      "provider": "openai",
      "model": "gpt-4-vision-preview",
      "apiKey": "sk-xxx",
      "apiBase": "https://api.openai.com/v1"
    },
    "fallback": {
      "provider": "anthropic",
      "model": "claude-3-opus-20240229",
      "apiKey": "sk-ant-xxx",
      "apiBase": "https://api.anthropic.com"
    },
    "strategy": {
      "enabled": true,
      "retryCount": 2,
      "timeoutMs": 30000
    }
  }
}
```

**配置管理功能**：
1. **热重载**：支持运行时更新配置（无需重启）
2. **配置验证**：启动时验证配置完整性
3. **敏感信息保护**：API密钥不记录日志
4. **配置版本控制**：支持配置文件版本管理

## 5. 架构设计原则

### 5.1 核心原则

1. **简洁性**：选择成熟稳定的技术栈，避免过度设计
2. **可维护性**：模块化设计，清晰的职责划分
3. **可扩展性**：为未来功能预留扩展点（如商业化）
4. **安全性**：认证授权、数据加密、审计日志
5. **可观测性**：日志、监控、LLM用量追踪

### 5.2 降级策略

```
┌─────────────────────────────────────────────────────────────────┐
│                    LLM 降级策略                                 │
│                                                                 │
│  配置检查                                                       │
│      │                                                         │
│      ├─ 降级未启用 ──→ 仅使用主LLM                              │
│      │                                                         │
│      └─ 降级已启用 ──→ 主LLM调用                                │
│          │                                                     │
│          ├─ 成功 ──→ 返回结果                                   │
│          │                                                     │
│          ├─ 失败/超时 ──→ 重试 (可配置次数)                     │
│          │                                                     │
│          ├─ 仍失败 ──→ 切换降级LLM (可配置)                     │
│          │                                                     │
│          ├─ 降级LLM成功 ──→ 返回结果                           │
│          │                                                     │
│          ├─ 降级LLM也失败 ──→ 系统降级模式                     │
│          │   • 识别失败：提示重拍                               │
│          │   • 手写批改：提示手动输入答案                       │
│          │   • 引导问答：显示已配置的引导路径                   │
│          │                                                     │
│          └─ 所有LLM不可用 ──→ 系统降级模式                     │
│              • 仅使用本地功能                                   │
│              • 记录失败日志                                     │
│              • 管理员告警                                       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 5.3 安全设计

| 安全措施 | 说明 |
|----------|------|
| **认证** | JWT Token，有效期控制 |
| **授权** | 基于角色的访问控制 (RBAC) |
| **密码** | bcrypt哈希，强制复杂度 |
| **传输** | HTTPS全站加密 |
| **存储** | 敏感数据加密存储 |
| **审计** | 关键操作日志记录 |
| **CORS** | 限制跨域访问 |
| **限流** | API调用频率限制 |

### 7.2 认证流程

```
┌─────────────────────────────────────────────────────────────────┐
│                    JWT 认证流程                                 │
│                                                                 │
│  客户端 ──→ POST /api/auth/login ──→ 服务端                    │
│    │                                      │                     │
│    │ 1. 发送用户名+密码                   │                     │
│    │─────────────────────────────────────→│                     │
│    │                                      │ 2. 验证密码         │
│    │                                      │ 3. 生成JWT         │
│    │ 4. 返回access_token + refresh_token │                     │
│    │←─────────────────────────────────────│                     │
│    │                                      │                     │
│  后续请求: Authorization: Bearer <token>                       │
│                                                                 │
│  Token刷新:                                                    │
│  POST /api/auth/refresh ──→ 新token                            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```
